# Kroscloud fork of @sparkjsdev/spark — change log

This is a fork of [sparkjsdev/spark](https://github.com/sparkjsdev/spark) maintained by
Kroscloud, branched from upstream tag `v2.1.0` (f22236f). Upstream is MIT-licensed by
World Labs Technologies, Inc.; the upstream `LICENSE` file is retained unchanged.

Fork purpose: add an **additive WebGPU render path** (TSL node material + GPU radix
sort) for three.js `WebGPURenderer`, replacing Spark's WebGL2 readback→CPU-sort
pipeline on capable devices. The WebGL2 path stays byte-identical to upstream and
remains the default/fallback (`webgpuPipeline: 'off'`).

Conventions:
- All new code is additive under `src/webgpu/`.
- Every touched upstream file carries a `Modified by Kroscloud, 2026` header comment
  and is listed here.
- No upstream file is reformatted (biome untouched); diffs are kept minimal for
  rebase-on-tags maintenance.

| `src/shaders/splatVertex.glsl` + `src/webgpu/SplatNodeMaterial.ts` (kroscloud.11, **[ssog-8]**) | **Far-view dense-region black-patch fix** (fill-V2 gate semantics corrected to upstream): the SSOG_FILL_V2 alphaClip discard and contribution cull now test the **RAW file alpha (pre-blurAdjust) against the POST-blur (dilated) det** — PlayCanvas compute-path semantics (`compute-gsplat-common.js`), where the blur term floors the contribution of point splats (`→ a·2π·blurAmount` as σ→0) so opaque sub-pixel splats survive. The previous form gated on the post-blurAdjust alpha, which cancels the dilation algebraically (`a·√(detOrig/det)·√det ≡ a·√detOrig`) and therefore tested TRUE undilated ink: with the app's `ssogMinContribution=1.0` it vertex-deleted the ENTIRE σ≤0.4 px projected population at ANY opacity — at whole-scene zoom the densest regions have the smallest per-splat σ, so exactly they blacked out (user-reported vs superspl.at; 6-agent adversarially-verified investigation 2026-08-19). The redundant `minPixelRadius=1.0` app policy deleted the same population (σ<0.316 px), which is why zeroing either knob alone never fixed it in the field. On the WebGL2 leg (preBlur 0.3, blur 0) `blurAdjust≡1`, so this shader change is a no-op there — the fix binds on the WebGPU leg. App-side pairing (not in the fork): `ssogMinContribution` 1.0→0.25 (their `minContribution=1` lives in a 2×-pixel unit convention — focal=2fx — so 0.25 is the true-pixel equivalent) and desktop `minPixelRadius` 1.0→0.0. | `src/shaders/splatVertex.glsl` + `src/shaders/splatFragment.glsl` + `src/webgpu/SplatNodeMaterial.ts` + `src/SparkRenderer.ts` + `src/webgpu/WebGpuSplatBackend.ts` (kroscloud.12, **[ssog-9]**) | **Expected-depth PICK mode** (Viewme `splat-measurement-precision-plan.md` Track A — the supersplat-viewer `picker.ts` mechanism, re-implemented): three new runtime uniforms on BOTH legs — `pickMode` (float 0/1; WGSL bans bool uniforms), `pickNear`, `pickFar` — plus a new varying `vViewZ` (view-space splat-CENTER z, constant across the quad). With `pickMode` 1 the fragment emits premultiplied `(normDepth·a, 0, 0, a)`, `normDepth = (−vViewZ − pickNear)/(pickFar − pickNear)`, so the EXISTING ONE/ONE_MINUS_SRC_ALPHA blend on color AND alpha over a (0,0,0,0)-cleared RGBA16F target accumulates `R = Σ aᵢdᵢ·Tᵢ`, `A = 1 − T` and the app reads back `R/A` = the transmittance-weighted expected depth (no blend-state override ⇒ no WebGPU pipeline rebake for the mode itself; the offscreen target still rebakes once — measured P0b: 235 ms WebGL2 / 20 ms WebGPU). `pickNear/pickFar` are a DEDICATED depth-normalization window for the fp16 quantization, NOT the camera near/far: every vertex-stage cull stays identical, so the pick footprint equals the displayed footprint. The GLSL pick branch lives ONLY inside the `PREMULTIPLIED_ALPHA` arm (the `#else` arm pairs with SRC_ALPHA/OMSA blending, under which `a·d` would be alpha-multiplied twice and R/A would break silently). Pinned (P0c, `poc/webgpu-splat-p1/p0-pick.js`): the identity holds BECAUSE both legs draw back-to-front (oldWorker most-distant-first; WebGPU inverted-key ascending radix) — a front-to-back order would need ONE_MINUS_DST_ALPHA/ONE instead, so any sort-direction change must re-run P0c. Default OFF (`pickMode` 0) ⇒ the color output expression is the unchanged premultiplied `vec4(rgb·a, a)` — byte-identical on both legs (P4 floor). Plumbed as `SparkRenderer` options/fields → the WebGL2 uniform sync in `onBeforeRender` and the backend's `applyPerFrame`. |
| `src/pcsogsDecode.ts` (kroscloud.13, **[ssog-10]**) | **SOG `shN` centroid stride fix.** Upstream indexes the k-means centroid image with a hard-coded 15-coefficient stride (`col = (label & 63) * 15`). splat-transform >= 3.x writes `shN_centroids.webp` at `64 * shCoeffs` px (3 / 8 / 15 for bands 1 / 2 / 3) — verified on the tank scene (`6vi2`, SH2: 512 × 1024 for 65 536 centroids) — so for SH1/SH2 files every lookup landed on a wrong centroid and the evaluated SH was noise: washed-out colour, blue/white blotches over the hull, invisible on SH0 scenes. Stride is now `centroids.width / 64` (writers have always packed 64 per row); sh1/sh2/sh3 offsets unchanged (`+0`, `+3`, `+8`). Shared by the static SOG path and the ssog unit decode (same function). Upstream `main` still carries the hard-code. |

## Behavioral deviations from upstream (WebGPU path only)

Enumerated per the fork plan §4.3; the WebGL2 path is unchanged.

1. No Pass-A accumulator: SH is evaluated per-frame in the vertex stage (upstream
   evaluates at sort cadence) and the per-frame fp16 camera-relative center
   re-quantization is gone (≤1 fp16 ulp precision improvement).
2. Blending is `CustomBlending` with explicit ONE/ONE_MINUS_SRC_ALPHA on both
   channels (r185 WebGPU ignores `premultipliedAlpha` on `NormalBlending`).
